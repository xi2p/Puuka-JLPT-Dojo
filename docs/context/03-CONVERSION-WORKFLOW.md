# 03 新增试卷、转换和音频校正流程

目标是完整可作答、可续做、可复盘的成品。OCR、ASR、生成草稿或启动后台进程均只是中间步骤。不要因任务长就主动留给「下一轮」；遇真实额度/系统限制才落盘说明原因和剩余步骤。来源问题按既定降级规则继续，不反复等待同一缺件。

## 1. 开始前查重和续断点

1. 先读本交接入口、用户要求和当前代码；查看程序与题库两个 Git 状态，识别已有用户改动。
2. 递归查找所有 manifest，按 `manifest.id` 查重；核对 `docs/batch-progress.json`、`tmp/imports/<id>/checkpoint.json`、已有运行文件、对应 docs/imports 和 tests/fixtures。若卷已存在，先判断用户是要求修订还是新增，不能重复制作。
3. 核对是否已有同卷制作进程或子任务，避免多个写入者。优先完成当前未结束的卷；现有59套不是待转换队列。
4. 原件只读；所有新输出、下载、解压、临时文件在项目 `tmp/imports/<id>/`，工具和模型复用 D 盘。运行环境未确认前不下载大型依赖。

新版历史范围为2010年起，先N2后N1；旧制已取消。原件目录名称混乱，不能只按目录年份/级别或文件扩展名判断实际内容。

## 2. 来源盘点

对每份题目、独立答案、解析、听力题册、原文、录音分别记录：完整路径、字节数、页数/实际时长、是否有可提取文字、版本和缺件、所用角色。建议保存 `source-inventory.json`、`audio-inventory.json`、`source-review.md`。

原生 PDF 文字可提取并不意味着文字完整或顺序正确；扫描/竖排、多栏、嵌入图片和续页必须看实际页面。封面写31页不表示文件真的有31页。答案图和 Word 原生表格可能是独立答案的重要来源，不能忽略图片附件。

优先级按证据用途区分：原印刷扫描确定题面/分段/框线/下划线；原生Word或高清重排本用于辨字、补充对照；独立答案和解析用于答案核对；实际录音确定音轨内容和时间轴。各来源可能互相冲突，不能简单设一个「永远正确」的文件。

只有重排卷时明确注明不能认证原印刷版。参考资料的高亮、答案标记、解析说明、中文译文不能混进正式题干。网页不得自行给参考资料的异常加上「官方原题」身份。

## 3. 提取文字并构造草稿

先复用已有 native 文本、OCR 和页面图，不重新处理整套。PDF有文字层就先抽取；无文字层用本地渲染和Tesseract日文OCR。原流程常用PyMuPDF按页面长边约2400像素渲染，疑点另做放大；这只是已用参数，不是所有来源的固定分辨率。

OCR初稿按页面顺序保存，保留PDF页码与印刷页码映射。Tesseract `jpn --psm 6` 可作普通单块起点，多栏/竖排/图表须换合适识别方式或人工转录。不要把 OCR 的换行或句号当成真实段落边界。Word需保留段落/run下划线、表格行列/合并、图片内文字；旧 `.doc` 不应改扩展名冒充 docx。

逐组建立题目、阅读材料及关联，按实际题量编号。保留：

- 每个小题完整题干、全部选项、原顺序、目标词和词尾下划线、对话说话人换行。
- 排序题四个空格与星号的真实位置，不能一律第三格；有的卷第二格，有来源缺失者不能猜。
- 所有阅读文章、续页最后几行、题名、作者、引言、出处、脚注、「中略」、A/B材料。
- 信息检索的完整规则、金额、日期、条件、例外、表格列对应、合并单元格和图示箭头。

通用说明放 `group.instruction`，实际小题放 `question.text`。删除首题重复说明时，只删除经来源确认的说明前缀，不能误删文章开头、空格编号或引用句。不要将解析里的「持续状态」等注解混入题面。

文章/表格优先重建为可选择 HTML。复杂必需图示可用局部裁图，放运行 assets；整页扫描不是文字化交付。普通选项不放复杂HTML，用 `choiceColumns`、`choiceStyle` 等显式元数据。版式细则见04。

## 4. 独立答案与修正

先从**独立来源**登记答案序列，再与运行草稿比对，不能把生成后的 `exam.json` 重新抄成「独立基准」。当前 fixtures 常用 `readingAnswers`、`listeningAnswers` 的逐组数字字符串，加组题量、题号、排除题、来源及核验状态。

每题对照实际选项内容而非机械信任号码；不同版本选项可能调换。阅读要用全文与限制条件验证；听力用实际场景与原文验证。独立答案、解析、题面不一致时记录各自结论，不因两个文件抄同一错误就称已独立互证。

可确定的OCR错误应按源页修正；明确转录/编号错漏可用独立证据恢复。原来源中故意错误的干扰项不能「改通顺」。来源自身语病、重复选项、日期星期错误、星号错位等，要保留和注明；只有有可靠证据时才改。对答案缺乏唯一可靠结论，保留参考、写具体 `sourceNote` 并设 `excludeFromScoring: true`。

例如 N1 2024.12 的r-29/r-34按实际选项内容纠正号码，r-32/r-35/r-37仍不计分；N2 2025.07 前13题资料疑似混版，不能因语言直觉明显就全部恢复计分；N2 2021.12 r-43星号/解析冲突保留说明和既有计分。这些既有判断见06和逐卷记录，不能一刀切处理所有疑义。

## 5. 缺件的处理规则

| 问题 | 交付方式 |
| --- | --- |
| 单题缺上下文、选项损坏或答案不唯一 | 保留可见内容、具体sourceNote、不计分；不反向翻译解析补日文题面 |
| 缺录音、删节/答案/错版音轨，或完整原文无法核验 | 整套聴解不发布；文字阅读版正常交付 |
| 文字卷本身严重缺页，不能构成完整范围 | 记录缺页证据、状态 `skipped_source_issue`，不创建发布manifest，继续其他卷 |
| 只有重排参考本 | 可按可见来源核对交付，明确原印刷版式未认证 |

文字阅读版：manifest `listeningOmitted: true`，不填 `audio`；exam仍保留r和l两部分，`l.groups: []`；页面明确「聴解：本卷未收录」，无听力入口、音频接口404。不能用其他年份或占位音轨凑完整卷。已成功处理过的省略状态，不因下一次扫描仍找不到音轨就重开同一阻塞。

## 6. 音轨选取和压缩

先用ffprobe查看真实编码、采样率、声道、码率、容器时长，完整解码检查损坏；扩展名不能作为编码证据。N2 2021.12 的.mp3实际是AAC，曾为浏览器类型兼容转为标准MP3；这种修格式是特殊处理，不是普通低码率音频再压缩的理由。

核对整段是否真实完整：开头说明/例题、各問題切换、各报号、最后一组的段数和内容、是否删节/报答案、是否与原文相符。有的音轨省去通用说明但实际题目完整，可经内容核验采用；不能仅凭总时长猜完整性。

已确认的压缩策略：超过96kbps、尚未优化的原始MP3，使用现有FFmpeg `libmp3lame -q:a 2` 单次制作高质量VBR，保持采样率、声道、音量、内容、停顿和完整时间轴，不加速、不裁切、不去静音、不降噪。

示意命令（输入输出须替换为本卷已核实路径，输出放tmp）：

```powershell
& 'C:\ProgramData\chocolatey\bin\ffmpeg.exe' -nostdin -i '<源音频>' -map 0:a:0 -c:a libmp3lame -q:a 2 -map_metadata -1 '<tmp中的候选.mp3>'
& 'C:\ProgramData\chocolatey\bin\ffmpeg.exe' -v error -nostdin -i '<候选.mp3>' -f null -
```

第二条离线解码输出到null，不是播放。采用候选必须同时满足：确实变小、全轨解码无错、源/成品解码时间轴和容器时长差核对小于0.1秒、逐题起点在最终音轨复核通过。记录字节数、节省比例、参数、两种时长、SHA256及是否采用；必要时比较同窗口波形包络。没有体积收益、96kbps及以下、已优化过的音轨不重复有损转码。N2 2016.12候选时差约0.39秒不达标，保留原运行音轨就是正确结果。

exams只留最终使用的一份音轨；原件库不改。制作候选、恢复副本和台账放tmp。已有批压脚本 `tmp/audio-optimization/compress.py` 带哈希断点；不丢台账后盲目重跑，也不因为用户说「以后先压缩」就对已压缩音轨再压一次。

## 7. 不播放地核对原文和逐题起点

全程禁止触发音频播放。使用本地faster-whisper tiny/CPU int8作定位线索，常用 `language='ja'`、词级时间戳、VAD、`condition_on_previous_text=False`，结果增量落盘为asr.json。不要上传录音或下载更大的模型来替代核验。

1. 全轨ASR找到「問題、一番、二番」及内容线索，人工将场景映射到题册/原文；排除说明、例题和重复报号。
2. 对候选起点做局部窗口ASR，核对题号和首句。窗口长度按录音调整，旧脚本有约13/20余秒等不同做法；不是固定所有卷同一秒数。
3. 用VAD或约10ms RMS包络校正真实语音开头，在报号/必要引导前保留适当余量，常约0.3—0.8秒；不要在话音中间开始。
4. 核对实际场景和组顺序；全轨ASR可能把当前报号归到前题、把例题当正题、在现场噪声中幻听数字。小模型文本不能直接当最终原文。
5. 在最终压缩/兼容转换后的运行音轨上再次核验范围、组内顺序和场景。保存候选、修订、判定方法及证据文件。
6. 同段对话多个小问共用同一 `audioStart`；小题数量可多于独立场景数。不要等分时间或为第二问编新起点。

现场录音报号无法精确识别时，只有场景已可靠确认才能采用保守前导，并明确注明 `scene_with_conservative_preroll` 等真实方法；可能多留几秒，不能冒称逐字精确报号。完整原文仍无法恢复/核验则按整套听力省略规则处理。N2 2021.12是保守前导案例，N1 2023.12是原文缺损导致省略案例。

`group.transcript` 应来自真实完整来源并与录音核对，修正文中可确认的转录错误；不确定人名、话者归属或句子保留说明，不制造貌似完整台词。原文必须保留末段和最后小问，不只抄ASR识别到的部分。

## 8. 草稿、入库和断点

推荐目录按现有卷复用：`source-inventory.json`、`checkpoint.json`、native/OCR、reading-final.json、listening-final.json、exam-draft.json、`audio/asr.json`、cues/verification、`runtime/`候选、`verification.json`。不是必须所有卷文件名相同；在报告中写准确路径。

**候选manifest先放tmp验证**。构造完整exam及assets，用隔离题库根加载候选，确保结构、题量、答案基准和页面可用。之后才把运行文件移到正式卷目录，正式manifest最后落盘，避免把半成品暴露给用户。维护机最终位置是`exams/exams/<id>/`；如果先暂放外层`exams/<id>/`，导出脚本可原地归位，但绝不能保留两份同ID。

每个实质步骤更新checkpoint：卷ID、状态、已完成和剩余步骤、使用来源、音轨哈希和压缩选择、疑题/省略范围、证据路径、验证结果、当前提交/推送情况。批次队列更新 `completedExamIds/currentExamId`，只有验收通过才写completed；来源跳过单独登记，不伪称完整。

最终完成标准：可作答的运行文件、独立答案fixture、具体来源说明、必要的视觉/内容回归、结构和内容检查、测试、隔离页面/接口验收及准确的发布状态。若当前任务含发布，必须按04分仓提交并核验远端；若不含发布，保留可审阅改动，不把「本地完成」写成「已推送」。
