# 04 视觉校对、验收、发布与排错

## 视觉校对不只是改 CSS

用户要求使题面尽量贴近原卷，范围覆盖全库；最早被指出的2017.7 N2問題9只是一个例子。原问题既有样式，也有制作脚本把句号直接拆成段落、将规则改写成简表、漏下划线和跨页内容等数据错误。

每卷先定位原件，建立「PDF页码—印刷页码—题组/文章/小题」映射，核对现存所有实际题页。原扫描决定分段与框线，高清重排本仅辅助辨字；只有重排资料时如实标注来源限制。后期逐卷记录及视觉fixture是本轮修订的重要证据，不得退回较早制作稿的排法。

| 对象 | 具体校对内容 |
| --- | --- |
| 文章段落 | 真正首行缩进、段尾、跨页续句；独立引言、题名、作者、中略及结语；不可按句号或OCR换行机械分段 |
| 下划线 | 完整覆盖被指代的词组/词尾；引用编号与下划线分开；清理交叠/嵌套坏标签；原文没划线处不能新增 |
| 填空/排序 | 原括号/方框/横线形式、编号、四格、第二或第三格星号；缺原线者保留来源说明，不能凭宽度猜 |
| 信件通知 | 日期、称呼、收件人、署名、公司、主题、敬语、记/以上、头尾位置及实际外框；不要套用来源没有的信件模板 |
| A/B材料 | 两份材料各自段落、标签、出处、边框；有的卷无外框，不统一强加 |
| 脚注和出处 | 原注号与正文对应，全部保留；从正文单独呈现，避免把脚注混入句子或因换行漏掉 |
| 竖排 | 来源要求时用可选择文字的竖排容器；材料内水平滚动，脚注可独立横排，不用整张截图替代 |
| 信息检索 | 原有物理列、合并单元格、灰色行标题、栏目层级、全套条款和附注；不自造表头，不改成归纳表 |
| 流程图 | 保留分支条件、方向及最终方案对应；文字型流程尽量可选择，不能把不等价表格当恢复 |
| 选项 | 按原件1/2/4列、独立便条边框、原换行和对话说话人；窄屏合理转列 |
| 图示 | 只采用核对过的必要局部；颜色/编号/箭头若参与判断必须保留；缺失原图不能反推重画 |
| 题面交互 | 题号下空心旗/实心旗，和首排选项同排；选项紧邻题干；目录不换行且右侧数量对齐；所有答题卡无旗子 |

已有的重要反例：N1 2024.12助成金案内实际是七项说明，后来撤掉此前人为增加的费用表；N2 2011.7搬家方案从流程图简化为表格时曾颠倒プランⅢ/Ⅳ条件，后按原卷修复；N2 2010.12说明会表有真实合并单元格，不可摊平成新列。可在[逐卷记录](../VISUAL-PROOFREADING.md)查对应详细依据。

## 基准和检查能证明什么

`tests/fixtures/<id>.json` 保存独立答案、题量、题号、排除题与来源等；`tests/fixtures/visual/<id>.json` 保存已审阅材料的文本哈希、题目/选项/答案/计分保持性，有些还记录音轨/原文/起点哈希。各卷 `source-layout-*.test.js` 验证具体段落数量、框线、表格结构和听力保持性。

视觉修改前记录当前内容基线，区分只调整HTML、按来源补回遗漏文字、修正题面/答案三种情况。只改版式时，去标签后正文、题目、选项、答案、计分和听力应保持；若来源支持文本修正，写清旧值、新值、原页依据，再更新基准。不能从错稿直接生成新哈希，让「测试通过」替代来源核对。

```powershell
node scripts/check-exams.js
node scripts/audit-instructions.js
node scripts/audit-content.js
npm test
```

结构/答案一致性测试不等于原文逐字正确；内容审计是候选检查，不会自动改题；4项重复选项警告已逐页对照来源，应保留而非为了零警告瞎改。视觉哈希确认没有无意删改，不能单独证明版式正确或来源正确。检查原件和桌面/手机实际页面都是必要环节。

注意：不少逐卷测试在本机未安装相应卷时会skip。新克隆的程序仓库不含exams，测试全绿可能只是没测题库；报告要说明已安装卷数和skip，不能把空题库测试当作59套内容验收。只有文档变更时核对文本、事实和链接，不需要为文档重复运行全量页面测试。

## 隔离的页面与接口验收

使用自己选定且未占用的端口、独立进度文件。PowerShell示例：

```powershell
$env:JLPT_PORT = '3371'
$env:JLPT_STATE_FILE = 'tmp/manual-review/progress.json'
$env:JLPT_NO_BROWSER = '1'
node server.js
```

需要候选题库时再设 `JLPT_EXAMS_DIR` 为tmp候选根；同一进程两个环境变量同时生效。该文件的浏览器也须隔离：localStorage按origin分开，端口变更可隔离正式3300的浏览器备份。不要在已有正式标签页直接做测试/导入记录。健康探测确认自己启动的实例；若命中现有用户服务，不要直接关闭它。

验收覆盖与改动相关的部分：

1. 目录、题量、只读版提示，完整题组和全部关联文章/续页/脚注/图表；桌面和手机重点检查宽表、长标题、竖排、选项和旗子。
2. 实际选择代表题、保存退出、继续恢复到原组，旗子与笔记保留；单次删除只影响指定attempt。正常卷、来源疑题和文字阅读卷按需覆盖。
3. 交卷后锁定，正确答案/来源说明/听力原文可见；按已知答案验证总分、各部分分母、不计分题和错题跳转。
4. `/api/exams`及对应卷、library-status无新增错误；音频API离线解码字节/SHA256与磁盘一致，文字阅读版音频返回404。
5. 检查播放器元数据、时长、资源URL、paused/currentTime及定位元数据；**不得点击播放、拖动后触发播放或调用play()**。可在测试上下文拦截HTMLMediaElement.play，作为意外触发保护；静音本身不等于遵守禁止播放。
6. 只有本机服务连接模块改动时才测试自己的服务停止/恢复，确认断开提示和待存数据恢复；不要关闭用户服务来做演示。

结束后只关闭自己创建的标签/服务，记录验收状态。开发进程如需后台启动，Windows `Start-Process` 使用隐藏窗口；保存PID以免误杀其他Node进程。不要读取用户个人答案来构造测试。

## 双仓库发布

用户已在原项目后期授权完成验收后提交并推送相关更新。后续按当前任务授权继续，区分正常维护推送与历史一次性强制覆盖；此交接本身没有创建新发布任务或无限强推权限。

开始先分别核对根程序仓库和exams题库仓库的status、branch、remote。主仓库应是GitHub程序地址，题库是浙大GitLab lib地址，均master。后期迁移已重建旧主历史，旧克隆不要把含音频的历史合并回来。

题库有任何JSON/资源改动，都必须更新catalog，否则客户端可能不显示更新、下载哈希校验失败。流程：

```powershell
node scripts/check-exams.js
node scripts/audit-content.js
npm test
node scripts/export-library.js
git -C exams status --short
```

导出会校验全部卷、将外层临时新卷归到`exams/exams/<id>/`并写`exams/catalog.json`，不复制整套音频也不做Git操作。它会移动路径，执行前确认独立仓库及无重复ID。只想验证目录时用 `node scripts/build-library-catalog.js exams tmp/library-export/catalog.json`，不改正式catalog。

审阅题库差异，暂存具体卷与catalog，一起提交：

```powershell
git -C exams add -- exams/n1-2024-12/exam.json catalog.json
git -C exams diff --cached --stat
git -C exams commit -m "Correct verified question content"
git -C exams push origin master
git -C exams rev-parse HEAD
git -C exams ls-remote origin refs/heads/master
```

示例中的卷路径须替换为实际受影响文件；新卷还包括manifest及必要assets。不要盲目`git add .`夹带其他正在进行的修订。题库`.gitattributes`的`* -text`很关键：SHA256以原字节计算，自动LF/CRLF转换会使远端文件与catalog不符。

程序仓库另行暂存代码、tests/fixtures、用户/维护文档，提交并正常推送；不包含exams、个人data、.runtime、tmp、tools、docs/imports、batch-progress、制作截图或本地文字archive。不要用`git add -f`绕开忽略规则。只改题库但同步了独立基准时，两仓库都可能需要提交，报告各自提交号。

推送后用远端分支SHA对照本地HEAD。网络、认证、校园网络、额度或冲突失败要说明具体阻碍和本地提交，保留成品，下次补推；不能写成已经发布。无需打开或生成访问令牌写入URL，凭证不进入文档和仓库。

## 常见维护陷阱

| 现象 | 先排查什么 |
| --- | --- |
| 本地没有某卷 | manifest是否有效、是否多层扫描到、是否重复ID隔离；不要只看某一层文件夹 |
| 下载更新始终报哈希错 | catalog是否随内容一起更新、题库是否换行被转换、同提交的文件是否一致 |
| 程序更新后题库没增加 | 这是既定分离机制；要刷新题库目录并选择下载，不把exams加回主仓库 |
| 页面显示旧样式/旧接口 | 保存退出后重启自己的服务、Ctrl+F5；不要先改正式进度 |
| IDM中断音频 | Blob加载和本机MP3入口是否被回归；旧兼容单卷URL是否被误用 |
| 点击题目A却跳题B | `audioStart`是否基于最终音轨、cues是否覆盖、共享场景映射和过时异步请求是否取消 |
| 未下载卷记录不显示/导入失败 | 验证器必须允许尚未下载卷的合法记录；记录不能因卸载题库被删除 |
| 旗子占一行、选项离题干很远 | `.question-options-row`布局与题号列，不只是图标尺寸；同时检查空options听力题 |
| 目录题类错位或换行 | 标记统计应在已答/总数最右、各列独立，不能把旗子插在标题前 |
| 修改答案后旧成绩变化 | 旧attempt保存答案而非固定分数，复盘按当前试卷重新计算；保持ID并解释修正依据 |
| 程序仓库体积仍大 | 当前工作树与.git历史对象分开判断；历史重建是已做的一次操作，不可擅自重做 |
| Git报dubious ownership | 核对确实是该工作区后可单命令 `git -c safe.directory='<已确认的绝对根>' ...`；不必修改全局配置或删除.git |

本轮没有发现需要通过猜题或反复重新识别相同缺件来「清零」的待办。来源无法解决的问题详见06，下一步应等待新可靠原页或当前用户给出的具体修复任务。
